**Who wrote it:** Support Ops (support-ops@clouddesk.example), v0.3.1, delivered as source in `third_party/ticket_history_server/`, unsigned, not reviewed by the agent team, and it reports an empty `serverInfo.version`, so we cannot tell later which build we are running.
**What it can reach:** every ticket and escalation in its store, for every customer (no per-customer scope). It runs as a stdio child with our user's file and network rights, and our client hands it the host's entire environment (`{**os.environ, **env}` in `mcp_client.py`), so it can read every secret the host can.
**What it logs:** every tool call, with the ticket id and the first 8 characters of the token, appended in plaintext to `week9/logs/ticket_history_access.log` (no rotation, no redaction) and echoed to stderr, which our client keeps in memory.
**What a stolen token could do:** the token is a static, non-expiring string committed to git in `week9/mcp_config.json`, so anyone with repo access can read every customer's ticket and escalation history, including staff names and refund amounts. The server has no write tools, so the risk is disclosure, not tampering.
**Ship or don't:** don't ship as configured. Ship for the handover once the token is out of git and rotated, the client passes the server only its own variables, and it runs behind the gateway with `get_escalation_history` denied, the history attached as a resource instead.
